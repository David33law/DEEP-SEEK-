# 06 — ARCHITECTURE DISCOVERY PROTOCOL (v1.0)

## Scope
Candidates = load-bearing MECHANISMS behind frozen ports (e.g. analogical transfer,
hypothesis generation, adversarial legal review, defeasible reasoning, self-improvement
evaluation). One load-bearing mechanism per candidate. Whole-system candidates forbidden.

## Freedom clause
The builder is NOT limited to the eight CP6 candidates. Allowed, with justification citing
the REPOSITORY-REALITY-MODEL and HISTORY table: revisit old architectures; combine them;
reject unproductive assumptions (e.g. documented E1 lessons); propose new families;
create successor mechanisms; trigger architecture review on stagnation (per 14).

## Mandatory proposal object (no implementation without ALL fields)
{capability_claim (measurable, ontology ids), load_bearing_mechanism, required_substrate,
expected_observable_behavior, failure_hypothesis, ablation_definition, fidelity_criteria,
development_tests, transfer_prediction, legal_use_prediction}.
Reject rule: architecture without measurable capability claim NEVER enters CANDIDATE_BUILDING.

## Tournament rules
Same substrate commit, same fixtures/seeds, same budgets, same verification pipeline (13).
Selection by per-capability deltas vs baselines + fidelity + ablation causality, not by
aggregate score alone. All proposals, rejections and reasons are ledger events (auditable).
