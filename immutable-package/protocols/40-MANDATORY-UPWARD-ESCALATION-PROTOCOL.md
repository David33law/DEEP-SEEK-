# 40 — MANDATORY UPWARD ESCALATION & ANTI-SATISFICING PROTOCOL (v1.3)
Purpose: the builder must never behave as a clerk selecting the first adequate architecture.
The experiment enforces disciplined upward search toward the strongest EVIDENCE-SUPPORTED
realization of the Charter objective.

## 1. No premature completion
The first candidate that passes visible, hidden, transfer and ablation gates is labeled
ONLY: **PROVISIONAL_FRONTIER_MEMBER**. It may not be called final architecture before the
mandatory successor and challenger rounds (44) and the anti-satisficing audit (43) complete.

## 2. Canonical escalation flow
candidate passes → provisional frontier (46) → ceiling analysis (45) → successor generation
(44) → challenger engineering/evaluation (same substrate, 13 equality) → Pareto comparison
(42) → anti-satisficing audit (43) → ESCALATE (new round) or FREEZE (dominance-reviewed).

## 3. Stop conditions (exhaustive; counters forbidden)
Stopping because of attempt counts is FORBIDDEN. Legal stops ONLY:
(a) verified target attainment (17 + 38 where applicable);
(b) documented frontier exhaustion (FRONTIER_EXHAUSTION_REVIEW: all four challenger types
    of the last round DOMINATED with evidence, and no undominated NEXT-ALTITUDE hypothesis
    remains fundable within remaining budget);
(c) evidenced architectural impossibility (impossibility argument recorded as ADR with the
    blocking invariant/bottleneck and what evidence would overturn it);
(d) explicit resource-budget exhaustion.
On (d) the output is labeled **BEST_DISCOVERED_SO_FAR** — never "final", never "highest",
never "supreme". Language rule enforced by audit (22, R10).

## 4. Reconciliation with budget discipline (14) — binding
Escalation is mandatory WITHIN budget, never beyond it. Frontier/dominance advance counts as
PROGRESS for 14's windows. Escalation never overrides stop conditions; anti-satisficing must
not become anti-shipping: if 43 findings are resolved and no challenger dominates, freezing
is legitimate and required. No round counters anywhere; exhaustion is proven by dominance
evidence, not by counting.

## 5. Roles (independence)
Distinct builder-model contexts with distinct role prompts: builder · architecture theorist ·
adversarial critic · simplification critic · legal-capability critic · migration critic ·
verification critic · future-scale critic. THE BUILDER NEVER CERTIFIES ITS OWN SOLUTION:
certification paths run through critic contexts + deterministic harness + independent audit (22).
Role-context configuration is an owner decision input (24 §11).
