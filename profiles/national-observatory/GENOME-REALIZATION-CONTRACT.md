# National Legal Observatory — Controlled Genome Realization Contract v6

## 1. Purpose

A controlled architecture genome is a search-space identity, not proof that the implementation realizes the declared architecture. A candidate that changes labels or constants while retaining one generic mechanism must not receive credit for a distinct family.

Every surviving architecture must therefore prove that all thirteen controlled axes are load-bearing in its actual semantic, durable, distributed, scale, bounded-formal and interoperability artifacts. Citation validity is necessary but is not itself causal evidence. Replication and crown additionally require executable source ablation, exact-source evaluator receipts, inert controls and an independently observed behavioral failure specific to the claimed axis.

The axis-probe evaluator is itself trusted protocol code. It cannot become authoritative merely because it exists or returns plausible reports. Its exact bytes, thresholds, routes and positive/negative behavior must be owner-bound and exhaustively calibrated before any production launch.

## 2. Required axes

The audit covers exactly:

1. canonical authority seat;
2. evidence primitive;
3. identity model;
4. state-derivation model;
5. temporal model;
6. normative-effect model;
7. consistency/commit model;
8. replication/distribution model;
9. trusted-core topology;
10. provenance/proof model;
11. publication topology;
12. governance/evolution model;
13. scaling/partition model.

The class reviewed for each axis must equal the frozen controlled class in the candidate genome. Free-form detail cannot change identity.

## 3. Independent realization auditors

Two independently prompted auditors receive:

- the complete blueprint and formalization;
- an AST-derived definition and symbol census for every candidate source artifact;
- bounded source excerpts;
- hashes of the complete source files;
- persisted semantic, durable, distributed, scale, formal, interoperability and cross-model reports;
- the exact controlled genome.

Auditor A follows an invariant-to-code proof strategy. Auditor B follows a counterexample/removal strategy with an independently sampled response. Different role names alone are insufficient: their per-axis citation maps must differ materially while each map passes the trusted validator independently.

For every axis each auditor must identify:

- concrete AST definitions that implement the choice;
- the `INV-*` obligations governing it;
- persisted executable evidence bearing on it;
- the axis-specific behavioral failure predicted if the mechanism is removed or replaced;
- a falsifier for the realization claim.

A family name, imported symbol, comment, manifest constant or prose assertion alone is not realization evidence.

## 4. Mechanical citation validation

The trusted validator independently verifies that:

- every axis appears exactly once;
- every reported class equals the candidate genome;
- every cited definition exists in the AST census of the cited artifact;
- every cited invariant exists in the frozen formalization;
- every evidence path exists inside the current runtime and is content-hashed;
- every passing report records the SHA-256 of the exact source bytes it evaluated;
- stale, cross-candidate or failed reports are excluded;
- the required source and evidence groups for that axis are represented;
- each auditor uses a sufficiently diverse definition map rather than collapsing all axes onto generic entrypoints;
- both auditors report no blocker and an overall passing verdict.

A missing, invented, stale or source-mismatched citation rejects the audit even when an auditor says `realized=true`.

## 5. Required artifact groups

At minimum:

- authority, evidence and state derivation require semantic and formal artifacts;
- identity, temporal and normative-effect models require semantic, formal and interoperability artifacts;
- consistency and replication require distributed and formal artifacts;
- scaling requires the scale artifact;
- provenance and publication require semantic and interoperability artifacts;
- governance/evolution requires semantic extension behavior and formal obligations;
- trusted-core topology requires formal and durable executable artifacts.

Both members of each independent formal or interoperability pair are available to the auditors. Each auditor must cite every required group independently.

## 6. Causal source-ablation proof

Citation existence does not prove that a definition is load-bearing. During independent replication and final crown, every auditor-specific axis/group/artifact citation set is therefore tested causally.

For each obligation the trusted ablation engine must:

1. read the exact source bytes identified by the current source census;
2. deterministically rename the complete set of AST definitions cited by that auditor for that axis, group and artifact, leaving call sites unchanged;
3. compile the mutated source;
4. execute the corresponding hidden semantic or specialized durable/distributed/scale/formal/interoperability evaluator under a fresh deterministic seed;
5. persist both the mutated source and evaluator report;
6. persist the evaluator process return code and bounded stdout/stderr witnesses for specialized arenas;
7. verify that the evaluator report records the SHA-256 of the exact mutated source bytes;
8. classify timeout, OOM, missing output, container refusal, output flooding, harness failure and other infrastructure outcomes as non-evidence;
9. require a candidate-origin failure and the axis-specific behavioral proof defined below.

Every obligation from both independent auditors must be causally falsified. Unioning the two auditor maps into one oversized mutation is insufficient; each auditor's claimed definition set must fail independently.

## 7. Diagnostic attribution is not causal authority

A central function may be load-bearing while remaining irrelevant to the particular architecture axis for which it was cited. Therefore a generic candidate crash does not prove an axis. A failure somewhere in the same broad artifact group does not prove an axis either.

The following remain useful diagnostics but are never independently sufficient:

- the exception or report naming a removed definition;
- axis vocabulary appearing in the removed definition body;
- a failed test or counterexample path that identifies only the broad artifact group;
- text-token overlap between an error and an axis vocabulary;
- successful receipt metadata, manifest text, source labels or family names.

The diagnostic layer must still record:

- the exact failure-only payload fields inspected;
- `whole_receipt_searched=false`;
- matched hard dimensions or axis-specific failure tokens, when present;
- failed test and directed-test paths as supporting context;
- whether a removed definition was named;
- `removed_definition_name_is_sufficient=false`;
- `group_path_is_sufficient=false`;
- deterministic SHA-256 receipts for recovered AST bodies and normalized definition vocabulary;
- `diagnostic_failure_attribution_is_sufficient=false`.

These records explain a failure and permit independent review. They do not decide causal credit.

## 8. Authoritative baseline-versus-mutant axis probes

The authoritative causal attribution mechanism is `observatory-axis-probe-v1`, executed exclusively through the protocol-bound evaluator `private-evaluator/evaluator/observatory_axis_probe_arena_v2.py`.

For every auditor/axis/group/artifact obligation, the trusted runner must execute the same hidden axis probe twice:

1. **baseline probe** — against the exact original source bytes identified by the current source census;
2. **mutant probe** — against the exact load-bearing mutant produced for that obligation.

The pair must use the same:

- controlled axis and artifact group;
- deterministic hidden seed;
- full 64-character task-identity SHA-256;
- `probe_id`;
- expected controlled-class manifest values;
- trusted evaluator implementation and isolation policy.

Causal credit requires all of the following:

- the baseline report is `PASS`;
- the baseline report has `valid_execution=true` and `failure_origin=none`;
- every baseline axis check passed;
- the mutant report is `FAIL`;
- the mutant report has `valid_execution=true` and `failure_origin=candidate_axis_behavior`;
- at least one structured mutant axis check failed;
- the baseline report is bound to the exact original source SHA-256;
- the mutant report is bound to the exact mutated source SHA-256;
- both reports and both process receipts are persisted and independently hash-verifiable;
- `same_axis_probe=true`;
- `baseline_axis_probe_passed=true`;
- `mutant_axis_probe_failed=true`;
- `behavioral_axis_evidence=true`.

A probe outcome with `status=INVALID` is never evidence. Missing Docker/Podman, parent timeout, container transport failure, output flooding, missing report, malformed report, evaluator defect, source-hash drift or any other infrastructure/harness failure leaves the obligation open.

The axis probe must exercise behavior rather than labels:

- semantic axes use hidden generated legal-change scenarios or the governed extension interface;
- semantic thresholds are loaded from the owner-signed `PARETO-DIMENSIONS.json`, never duplicated in a second policy seat;
- durable trusted-core topology uses restart, integrity, canonical-root and publication behavior;
- distributed consistency and replication use partition, quorum, crash, heal and convergence behavior;
- scale uses deterministic ingestion, partition roots, restart and publication behavior;
- formal axes use hidden transition/query/publication scenarios specific to the claimed axis;
- formal order-independence is required only when the model manifest claims `commutative_independent_admissions=true`;
- formal load or operation failures must be represented by a structured false axis check rather than an empty or transport-only failure;
- interoperability axes use hidden canonical bundles and axis-specific identity, temporal, effect, provenance or publication projections.

Diagnostic token matching, definition-body vocabulary and broad group failures may be preserved alongside the probe pair, but `diagnostic_failure_attribution_is_sufficient` must remain `false`.

Every task in replication and crown must carry a complete passing baseline/failing mutant probe pair. The independent audit, deterministic supremacy dossier and external Docker E2E verifier must independently reopen and rehash both reports, reproduce pair identity and confirm that the number of valid probe pairs equals the complete task count. The dossier and E2E verifier must also bind the exact SHA-256 and byte length of `observatory_axis_probe_arena_v2.py`.

## 9. Owner-signed exhaustive evaluator calibration

The v2 axis-probe evaluator must be calibrated before it can judge any production architecture. Calibration is part of the owner ceremony and is an explicit signed mission requirement, not an optional developer test.

The owner-signed mission must contain `axis_probe_calibration_required=true`. A D09 row lacking that field is stale and must be rejected before launch.

Calibration must exercise every declared `(artifact group, controlled axis)` route in the probe contract. The current closed route set contains exactly twenty-eight routes:

- nine semantic routes;
- one durable-systems route;
- two distributed routes;
- one scale route;
- ten formal routes;
- five interoperability routes.

Each route must produce an independently persisted pair:

1. the exact calibration reference source must pass the v2 probe;
2. a mechanically controlled source mutation must fail with `valid_execution=true`, `failure_origin=candidate_axis_behavior` and at least one structured false axis check;
3. both executions must share the same `probe_id`, seed and expected-manifest digest;
4. reference and mutant source SHA-256 values must differ;
5. timeout, missing runtime, malformed output, output flooding, transport failure or evaluator defect must produce invalid calibration, never a successful negative witness.

The complete calibration therefore requires exactly:

- 28 valid probe pairs;
- 28 passing baseline reports;
- 28 candidate-origin failing mutant reports;
- 28 controlled mutant source files;
- 84 directly hash-verifiable evidence files in total;
- 0 provider or model calls.

The calibration source census contains exactly six reference candidates, the base probe arena, the v2 probe arena and the calibration runner. The owner ceremony must hash all nine files into the specialized-calibration receipt.

Independent verification is required at three distinct boundaries:

1. **owner ceremony** — `observatory_setup_v5.py` executes all routes and appends the source and campaign hashes to `observatory-specialized-calibration-receipt.json`;
2. **production preflight** — `observatory_preflight_v6.py` reopens and rehashes all six references, the exact v2 evaluator, all 28 mutant sources and all 56 reports before launch;
3. **external Docker E2E** — `prove_complete_observatory_protocol_calibration_hardened.py` independently reproduces the source, route, task-identity, report, failed-check and evaluator-hash census inside the disposable clone.

The static proof must import the v2 evaluator, execute its fail-closed patching, compare its semantic hard-minimum map to the owner-signed Pareto contract and verify the conditional formal-commutativity rule. The final proof must reject any disagreement between the static evaluator hash, the disposable-clone evaluator hash, the owner-ceremony calibration receipt and the runtime supremacy dossier.

Calibration proves that the evaluator routes can distinguish fixed passing references from controlled broken references under the exact tested paths. It is not evidence that a tournament architecture is superior, nor an unbounded proof that every possible faulty implementation will be detected.

## 10. Inert negative controls

A failed mutant is meaningful only if failure was caused by the cited mechanism rather than AST rewriting, source hashing or evaluator routing.

Before load-bearing mutations, the engine must run one inert negative control for every affected source artifact. The control appends an unreachable definition, deterministically renames only that unreachable definition, and reruns the same evaluator path. Every control must pass with a zero evaluator return code where a process receipt applies.

A failed control invalidates the causal environment. Infrastructure refusal, timeout, missing output, evaluator invalidation, source-hash drift or malformed reports never count as evidence that an architecture mechanism is load-bearing.

The inert mutation control and the axis-probe baseline serve different purposes. The inert control proves that AST mutation and evaluator routing are not intrinsically destructive. The baseline axis probe proves that the exact original source actually realizes the behavioral obligation being attributed.

## 11. Qualification, replication and crown

The complete citation/evidence realization audit runs:

- after qualification of every initial and round-created architecture;
- again after independent replication with fresh auditor calls and replication evidence;
- again at the final crown after all crown arenas have completed.

Qualification proves source/evidence binding across the broad field. Replication and crown additionally require the full auditor-specific causal-ablation campaign, inert controls and complete baseline-versus-mutant axis-probe pairs. No architecture revision is allowed during replication or crown realization audit.

Each causal campaign persists:

- candidate and phase identity;
- both auditor identities;
- all required auditor/axis/group obligations;
- every renamed definition set;
- every mutated source path and SHA-256;
- every evaluator receipt path and SHA-256;
- process return codes and bounded output witnesses for specialized evaluators;
- candidate-versus-infrastructure failure classification;
- failure-only diagnostic attribution;
- AST-body and normalized-vocabulary SHA-256 receipts;
- every baseline axis-probe report path and SHA-256;
- every mutant axis-probe report path and SHA-256;
- shared probe IDs, seeds and expected-manifest hashes;
- the full task-identity SHA-256;
- every structured baseline and mutant axis check;
- the exact v2 evaluator path, SHA-256 and byte length;
- all inert negative-control outcomes;
- verified axis, behavioral-probe-pair and obligation counts;
- an explicit proof boundary.

The genome-realization report binds the causal campaign path and SHA-256. The deterministic supremacy dossier independently rehashes the mutated sources, evaluator receipts and both axis-probe reports, verifies pair identity, process/source classification and axis behavior, indexes every baseline and mutant report directly, and binds the exact v2 evaluator bytes.

The exhaustive calibration independently persists its aggregate report, the specialized-calibration receipt, every controlled mutant source and every baseline/mutant report. Preflight and external E2E must rehash those bytes rather than trusting aggregate counts.

## 13. Owner-signed consequence

The owner-signed mission must require:

- `causal_genome_ablation_required=true`;
- `causal_genome_negative_controls_required=true`;
- `axis_specific_causal_attribution_required=true`;
- `axis_specific_behavioral_failure_required=true`;
- `axis_behavioral_probe_required=true`;
- `axis_probe_calibration_required=true`.

A signed mission lacking any of these requirements is stale and must be rejected before launch.

The following are explicit supremacy conditions:

- `genome_realization_proven`;
- `genome_realization_replication_passed`;
- `genome_realization_crown_passed`;
- `genome_causal_ablation_replication_passed`;
- `genome_causal_ablation_crown_passed`.

A missing axis, class mismatch, invented definition, missing `INV-*` obligation, stale evidence, generic citation map, auditor dependence, passing load-bearing mutant, weak or invalid baseline probe, passing mutant probe, incomplete or stale calibration, evaluator-byte drift, unrelated failure, group-only failure, definition-name-only failure, failing inert control or infrastructure-only failure blocks `COMMITTED`. Resource exhaustion yields only `BEST_DISCOVERED_SO_FAR`.

The causal proof is bounded to the exact cited source bytes, hidden corpora, fault workloads, calibrated axis-probe implementation, attribution mappings and definition-set mutations. It does not claim an unbounded theorem about all semantically equivalent rewrites or all future deployments.
