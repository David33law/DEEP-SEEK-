# NATIONAL LEGAL OBSERVATORY — WHOLE-SYSTEM ARCHITECTURE DISCOVERY PROTOCOL v1

## Scope
Candidates are complete executable architecture prototypes for the Observatory mission. The unit of competition is the whole system, not one isolated capability mechanism.

A candidate must define a coherent answer for: authoritative source acquisition; immutable evidence; canonical legal identity; temporal state; normative effects; jurisprudence linkage; doctrine/theory typing; provenance; unknown/conflict handling; publication/interchange; replay/recovery; governance and migration from the attested current repository.

## Blindness rule
The verified CP1 repository reconstruction is reusable baseline evidence. Earlier CP2 architecture research remains quarantined during independent Observatory design-space discovery. It may be revealed only after the new frontier has been independently generated, for adversarial comparison and missed-family detection.

## No architecture family is preselected
The builder may propose any technically constructible architecture. Event sourcing, graph databases, relational stores, content-addressed stores, Common Lisp kernels, polyglot boundaries, actor systems, formal state machines and federated source meshes are hypotheses, not requirements.

## Required candidate object
No candidate enters engineering without all fields:
- architecture_family and explicit differentiators from existing frontier members;
- trusted_boundary and complete authoritative-writer census;
- canonical data and identity model;
- temporal model distinguishing effective and knowledge time;
- normative-change semantics;
- jurisprudence and doctrine relation model;
- provenance/proof model;
- failure, recovery and deterministic replay model;
- publication/interchange model;
- migration/rollback path from the attested target repository;
- executable contract implementing the profile operations;
- falsifiable predictions for every Pareto dimension;
- named failure hypotheses and ablations;
- evidence explaining why a known higher conception is not currently supported.

## Design-space saturation
A fixed number of candidates never proves completion. The runner maintains families-known and families-tried. Search continues while an evidence-supported undominated family or next-altitude hypothesis remains. A renamed instance of an existing mechanism is not a new family.

## Tournament equality
All contenders receive the same attested target snapshot, mission charter, visible fixtures, resource budget class and verifier contract. Hidden replay cases, seeds and ground truth remain evaluator-only.

## Selection
No aggregate-score winner. A candidate survives only if every hard minimum passes and it is non-dominated on the Observatory Pareto dimensions. A first survivor is PROVISIONAL_FRONTIER_MEMBER only.

## Mandatory attacks before freeze
Every prospective winner must survive:
1. radical challenger from a different architecture family;
2. simplification challenger;
3. duplicate and conflicting-source injection;
4. late correction and out-of-order event replay;
5. amendment/repeal/suspension/revival/codification chains;
6. jurisprudence against historical provision versions;
7. doctrine-to-binding-authority contamination attempts;
8. crash, partial-write and full deterministic rebuild drills;
9. withheld/unknown evidence requiring explicit abstention;
10. independent completion audit and pairwise dominance review.

## Freeze semantics
Freeze is permitted only by verified target attainment, documented frontier exhaustion, evidenced impossibility, or explicit resource exhaustion. Resource exhaustion yields BEST_DISCOVERED_SO_FAR, never a final/supreme claim.
